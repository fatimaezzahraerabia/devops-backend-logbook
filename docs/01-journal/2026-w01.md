# 📓 Note de Journal — Semaine 01 (Initialisation du Projet)

**Date** : 2026-10-06  
**Auteur** : DevOps Candidate  

---

## 🎯 Objectif de la semaine
Mettre en place la structure initiale du carnet de bord d'ingénierie avec MkDocs Material, configurer le déploiement automatique sur GitHub Pages via GitHub Actions, et intégrer Decap CMS pour permettre la mise à jour dynamique des notes sans faire de `git push` manuel.

---

## ✅ Ce qui a été fait
- [x] Initialisation du dépôt Git et de l'arborescence des dossiers (`00-plan` à `07-cheatsheets`).
- [x] Configuration du fichier `mkdocs.yml` avec support du mode sombre/clair, du plugin de recherche et de Mermaid.js pour les schémas d'architecture C4.
- [x] Création du workflow `.github/workflows/deploy-docs.yml` pour compiler et déployer automatiquement le site lors d'un `push` sur la branche `main`.
- [x] Intégration de **Decap CMS** dans `docs/admin/` pour l'édition dynamique depuis le navigateur web.
- [x] Rédaction du plan d'apprentissage 90 jours et des modèles de fiches (ADR, Incidents, Projets, Journal).

---

## ⚠️ Bloqué / Cassé
> [!NOTE]
> **Problème rencontré** : Le rendu des schémas Mermaid ne s'affichait pas correctement en mode sombre sous MkDocs Material sans la configuration explicite de la clôture personnalisée `pymdownx.superfences`.  
> **Solution apportée** : Ajout de la clé `custom_fences` configurée pour `mermaid` dans `mkdocs.yml`.

---

## 💡 Ce que j'ai appris
- Comment intégrer un headless CMS sans serveur léger (Decap CMS) qui utilise directement les appels API REST de GitHub pour modifier des fichiers Markdown et déclencher un workflow de build sans passer par une ligne de commande local.
- L'utilisation des diagrammes Mermaid au format C4 Model pour représenter clairement les composants backend (API, DB, Cache, Workers) et le pipeline CI/CD.
